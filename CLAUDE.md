# DnD Map — инструкции для Claude

Интерактивная карта для настольных ролевых игр: pnpm-монорепо (`apps/server` — Fastify + Socket.IO + Prisma/PostgreSQL, `apps/web` — React + Konva, `packages/shared` — общий контракт).

## Прежде чем менять код

**Прочитай `docs/architecture.md`** — там устройство сервиса, протокол событий, модель данных, права, клиентское состояние и список инвариантов (§8), которые нельзя ломать. Читай нужные разделы перед работой с соответствующей частью кода, а не по памяти.

Другие документы: требования — `analitika-servis-karta-dnd.md`, план и решения по этапам — `plan-razrabotki.md`, развёртывание — `docs/deploy.md`.

**Поддерживай `docs/architecture.md` актуальным:** если меняешь протокол (и `PROTOCOL_VERSION`), модель данных, права, раскладку модулей или инварианты — обнови документ в том же изменении.

## Команды

- `pnpm dev` — сервер :3000 и клиент :5173
- `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, `pnpm build` — то же, что проверяет CI
- `E2E_BROWSER_CHANNEL=msedge pnpm test:e2e` — e2e в установленном Edge
- `pnpm --filter @dnd-map/server load-test` — нагрузка (сервер с `RATE_LIMIT=off`)

## Правила работы в этом репозитории

- Любое новое действие: схема и событие в `packages/shared` → проверка `can()` и транзакция с `bumpVersion` на сервере → рассылка по ролям → оптимистичное применение с откатом на клиенте → интеграционный тест, включая отказ без прав.
- Тест на защиту проверяй мутацией: временно сломай защищаемое место и убедись, что тест падает.
- Окружение: Windows, Node 24, pnpm 12 (`allowBuilds` в `pnpm-workspace.yaml`), локальный PostgreSQL 15 (пользователь/база `dnd_map`, тестовые `dnd_map_test`, `dnd_map_e2e`). Docker не установлен.
- Перед `prisma generate`/миграциями останови все процессы `pnpm dev` (включая дочерние), иначе EPERM на движке Prisma. `prisma migrate dev` неинтерактивно не работает — см. `docs/architecture.md` §4.3.
- Коммиты — только по просьбе пользователя. Общение с пользователем — на русском.
